# Languages

A portfolio is written in one main language (`Profile.defaultLocale`, English for existing profiles) and can offer up to 4 more (`Profile.locales`, `MAX_EXTRA_LANGUAGES` in `shared/src/languages.ts`). The list of languages, their scripts and directions lives in that one file.

## Pages

The main language stays at `/<username>`. Others are at `/<username>/<locale>` (and `/writing`, `/writing/<post>` under it). A language that is not added, or whose tagline and about are not yet translated, is a 404.

## Where the words are

- **The owner's text** is in the `Translation` table (one row per field per language). A missing translation falls back to the main-language text, field by field. Names, companies, links, dates, tech tags, the location and testimonials are not translated.
- **Interface text** (section headings, buttons, the testimonial form) is in `frontend/src/lib/i18n/messages/<code>.json`, with English as the fallback for any missing key. It is read with next-intl's `createTranslator` (ICU plurals), not its routing, because the language belongs to a profile, not to the whole site.

## Machine-written interface strings

Every file except `en.json` was written by a language model and has not been reviewed by a native speaker: hi, te, ta, bn, mr, gu, pa, ur, es, fr, de, pt, ar. Please have them reviewed before relying on them.

## Known limits

- The resume PDF is in the main language only.
- Share-card images (satori) show the tagline only for Latin-script languages; the others show the name and address.
- `<html lang>` and `dir` are set on a wrapper in the server HTML and on `<html>` by a small client component, because the root layout is shared by every page.
- The language links are a strip above the theme, not inside each theme's header.
- The dashboard stays in English. There is no analytics system, so there are no per-language view counts.
